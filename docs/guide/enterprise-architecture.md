# 企业级架构升级

::: tip 🎯 这页解决什么
帮你快速理解：为什么 `EZ Admin Gin` 不再只满足于“功能能跑通”，以及当前这轮结构升级已经走到哪一步。
:::

## 先看结论

`v1.1.0` 已经是一套完整可用的后台系统，但它更接近“功能型后台”。继续往上叠组织体系、数据权限、复杂查询治理时，如果还沿用原来的结构，成本会越来越高。

所以这轮企业级升级的真正重点，不是先加更多页面，而是先把底层结构和模块边界收稳：

- 启动入口从 `main.go` 的集中装配，升级为 `bootstrap` 聚合
- 技术基础能力收拢到 `platform`
- 路由和业务能力按模块拆成 `module/auth`、`module/setup`、`module/iam/*`、`module/system/*`
- 先把部门、岗位、角色数据范围这些基础模型和迁移打底
- 再把数据权限和模块边界收成后续可复用的接入主线

这一步的目标不是炫技，而是为了让后续的组织体系和数据权限能真正落地。

## 为什么 v1 结构不够了

当前仓库在 `v1` 阶段已经做对了很多事：

- 配置、日志、数据库、Redis、迁移链路都完整
- JWT、Casbin、菜单、按钮、日志、公告都已跑通
- 前后端和部署文档已经形成闭环

但如果目标升级为企业级底座，下面这些问题会开始放大：

- `handler` 里直接操作 `gorm.DB`，参数绑定、事务、查询拼装和业务规则混在一起
- 当前权限体系只解决“接口能不能进”，还没解决“进去后能看到哪些数据”
- 路由集中在一个文件里注册，模块一多会变成总装配文件
- 组织体系、数据权限和查询规则还没有稳定的落点

这也是为什么 `v2` 要先做结构升级，而不是只继续补模块。

## 当前已经收稳的骨架

当前后端主线已经基本收敛到下面这套骨架：

```text
server/
├── cmd/
│   └── server/
├── internal/
│   ├── bootstrap/
│   ├── platform/
│   │   ├── config/
│   │   ├── database/
│   │   ├── logger/
│   │   ├── redis/
│   │   ├── authn/
│   │   ├── authz/
│   │   └── datascope/
│   └── module/
│       ├── auth/
│       ├── setup/
│       ├── iam/
│       ├── system/
```

这一轮升级已经稳定下来的关键点是：

- `bootstrap` 负责启动装配和模块聚合
- `platform` 负责技术基础设施
- `module/auth` 负责登录、当前用户、菜单与首页摘要
- `module/setup` 负责一次性初始化入口
- `module/iam/*` 负责用户、角色、部门、岗位、菜单这类身份与授权资源
- `module/system/*` 负责配置、文件、公告、登录日志、操作日志这类系统资源
- `datascope` 负责企业后台常见的数据权限模型与查询过滤语义

## 这次升级和数据权限是什么关系

数据权限不是一条额外规则，而是整个企业后台结构是否合理的试金石。

如果系统里只有登录和接口权限，那么：

- 用户能不能访问“用户列表接口”已经够判断权限了

但只要进入企业后台，就会很快遇到第二层问题：

- 这个角色能不能只看本部门用户？
- 能不能看本部门及子部门？
- 能不能看自己创建的数据？
- 多个角色叠加后数据范围怎么合并？

这类问题如果继续堆在 `handler` 里，后续每个模块都会越来越重。  
所以 `v2` 明确把权限拆成两层：

- **接口权限**：决定“能不能访问接口”
- **数据权限**：决定“访问后能看到哪些数据”

接口权限继续用 `Casbin`，数据权限则已经沿着 `Actor + Merge(...) + gorm.Scopes(...) + module/*/datascope.go` 这条链路开始稳定落地。

## 这轮升级已经完成了什么

当前已经完成的，不只是“建立新目录”：

1. 建立新的后端骨架，让后续代码有稳定归位
2. 落组织体系和数据权限的基础模型与迁移
3. 把核心系统模块收进 `module/iam/*` 与 `module/system/*`
4. 把教程主线扩展成企业级完整版 9 章
5. 把部署、回滚、排障、长期运维和项目复用整理成完整交付说明

## 当前真正还剩什么

当前主线真正还在继续推进的，主要是三件事：

1. 把第 5 章继续收成最稳定的数据权限教学主线
2. 补齐数据字典、账户中心、附件中心和一个非 `system` 分组的真实业务示例模块
3. 建立登录、接口权限、数据权限、组织树和初始化迁移的最小测试基线
