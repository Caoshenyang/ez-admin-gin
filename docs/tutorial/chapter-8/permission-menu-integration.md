# 权限、菜单与迁移接入

把模块代码写完后，最常见的错觉是：接口能调通，模块就算接完了。

但对后台系统来说，真正决定一个模块能不能被使用起来的，往往是下面这些连接层：

- Casbin 接口权限
- 菜单树和按钮权限
- 超级管理员默认授权
- 前端动态路由与按钮消费
- 迁移文件里的初始化种子

::: tip 🎯 本节目标
读完这一节，你应该能顺着当前真实实现走通一条完整接入链路：

- 接口权限写进 `casbin_rule`
- 菜单和按钮写进 `sys_menu`
- 默认角色绑定写进 `sys_role_menu`
- 前端通过 `dynamic-menu.ts` 把页面和按钮权限真正消费起来
:::

## 先看当前主线里的完整接入链路

```text
module/*/policy.go
  ↓
migrations/*/seed data
  ├─ casbin_rule
  ├─ sys_menu
  └─ sys_role_menu
  ↓
/api/v1/auth/menus
  ↓
admin/src/router/dynamic-menu.ts
  ↓
前端页面与按钮权限消费
```

这意味着模块接入不是只补后端接口，而是至少要把：

- 接口能访问
- 前端知道它存在

这两层一起打通。

## 第一层：先把权限点收在 `policy.go`

当前更稳的做法，是在模块里先把权限点常量收稳，例如：

```go
const (
	PermissionList   = "crm:customer:list"
	PermissionCreate = "crm:customer:create"
	PermissionUpdate = "crm:customer:update"
)
```

这一步的价值是：

- 菜单按钮种子有稳定来源
- 前端 `canUse(...)` 有稳定命名
- 排障时知道这个模块到底有哪些动作点

## 第二层：Casbin 策略一定要进入迁移种子

当前默认权限不是靠启动后手工点出来的，而是通过迁移初始化。

所以一个要正式进入系统的模块，至少应该补：

- `GET /.../list`
- `POST /.../create`
- `POST /.../:id/update`
- `POST /.../:id/status`

这一类核心接口策略。

## 第三层：菜单和按钮不能只补页面入口

当前后台不是只有页面菜单节点，还包括按钮节点：

| `type` | 含义 |
| --- | --- |
| `1` | 目录 |
| `2` | 页面菜单 |
| `3` | 按钮权限节点 |

所以一个模块要进入系统，通常至少要补：

1. 目录或所属菜单组
2. 页面菜单节点
3. 该页面的按钮权限节点

## 第四层：`component` 字段必须和前端映射表一致

后端 `sys_menu.component` 不是任意字符串，它必须命中前端：

- `admin/src/router/dynamic-menu.ts`

里的 `routeComponentMap`。

否则前端即使菜单显示了，也只会回退到占位页。

## 第五层：默认角色绑定不能忘

把菜单和按钮写进 `sys_menu` 后，还要继续补：

- `sys_role_menu`

否则默认管理员登录后，系统仍然不知道应该把这些节点授权给谁。

当前更稳的默认做法仍然是：

- 先把系统内置能力默认授权给 `super_admin`

## 第六层：前端最终怎么消费这些东西

前端会通过：

- `/api/v1/auth/menus`

拿到完整权限树，再做两件事：

1. 把页面菜单节点变成侧边栏和动态路由
2. 把按钮节点 `code` 收成 `buttonPermissionCodes`

这就是为什么一个模块真正接完后，应该同时看到：

- 菜单入口出现
- 页面能打开
- 页面按钮显隐生效

## 这一页最短检查表

你可以直接按下面这张表做一次快速核对：

| 项 | 通过标准 |
| --- | --- |
| `policy.go` | 权限点常量已固定 |
| `casbin_rule` | 核心接口策略已入种子 |
| `sys_menu` | 页面节点与按钮节点已入种子 |
| `sys_role_menu` | 默认角色已被绑定 |
| `component` | 已命中前端白名单 |
| 前端页面 | 能从 `/auth/menus` 真正开页 |
| 按钮权限 | `canUse(...)` 能正确显隐 |

## 本节最关键的结论

模块接入如果只做到“接口可调”，它还只是后端半成品。

只有当：

- 接口权限
- 菜单入口
- 按钮权限
- 前端动态消费

一起成立时，它才算真的进入当前后台底座。
