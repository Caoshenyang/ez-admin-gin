# 后台布局与工作标签

登录成功后，前端不会直接进入某个孤立页面，而是先进入统一后台壳子：

- 左侧菜单
- 顶部栏
- 工作标签
- 主内容区

这一页对照当前真实的 `admin/src/layouts/AdminLayout.vue`，把这套壳子拆开来看。

::: tip 🎯 本节目标
读完后，你应该能看懂当前后台为什么可以稳定维持“一屏应用壳”的感觉，也知道工作标签、面包屑、退出登录这些能力分别落在哪一层。
:::

## 先看当前真实结构

后台壳子主要由下面几部分组成：

```text
admin/src/layouts/AdminLayout.vue
admin/src/router/index.ts
admin/src/router/dynamic-menu.ts
admin/src/utils/auth.ts
```

它们的关系是：

```text
router/index.ts
  ↓
AdminLayout.vue
  ├─ sideMenuOptions
  ├─ findMenuTitleByPath(...)
  ├─ getAuthUserInfo()
  └─ RouterView
```

## 当前后台壳子的第一目标是什么

不是“把很多组件堆到一起”，而是先把后台固定成一个稳定的应用框架：

- 左侧菜单固定
- 顶部栏固定
- 主内容区域由子路由切换
- 页面切换时保留工作台心智

这也是为什么 `AdminLayout.vue` 现在会围绕：

- `NLayout`
- `NLayoutSider`
- `NLayoutHeader`
- `RouterView`

来组织，而不是把每个页面各自当成一个独立站点。

## 侧边栏现在怎么工作

侧边栏核心依赖的是：

- `sideMenuOptions`
- `activeMenuKey`
- `handleMenuUpdate(...)`

其中最关键的一点是：

> 它已经不再维护自己的静态菜单数组，而是完全消费 `dynamic-menu.ts` 转换出来的菜单结果。

这意味着侧边栏本身不关心“当前用户有哪些权限”，它只负责把已经准备好的菜单状态渲染出来。

## 为什么有 `sidebarCollapsed`

当前 `AdminLayout.vue` 里保留了侧边栏收起能力：

- 展开时宽度 `240`
- 收起时宽度 `76`

这一步虽然只是一个 UI 细节，但它很重要，因为它让后台壳子从一开始就具备：

- 页面密度可调
- 小屏下的空间让渡
- 更贴近实际后台产品的交互感

## 顶部栏现在承载了什么

当前顶部栏主要有四类内容：

1. 面包屑文本
2. 搜索框占位
3. 工具按钮占位
4. 用户下拉菜单

其中当前真正已经接通主链路的是：

- 面包屑文本
- 当前用户显示
- 退出登录

搜索、通知、全屏、主题切换这些按钮目前更多是壳子级保留位，后续可以再继续接真实能力。

## 面包屑标题为什么能跟着路由变化

当前标题来源是：

- `route.meta.title`
- 或 `findMenuTitleByPath(route.path)`

也就是说，它优先使用动态路由注册时带进来的页面标题；如果没有，再回退到当前菜单树里查标题。

这样做的好处是：

- 页面标题不需要在布局里手写一张映射表
- 动态菜单来的页面和后台默认页能用同一套显示逻辑

## 工作标签为什么还值得保留

当前 `openTabs` 是一套非常轻量的工作标签实现，但它已经足够表达后台常见使用习惯：

- 打开多个页面
- 关闭当前页面
- 关闭其他页面
- 回到工作台

这套实现没有额外引入状态管理库，而是直接在布局里围绕当前路由维护：

- `ensureCurrentTab()`
- `handleCloseTab(...)`
- `handleCloseOtherTabs()`

当前选择这种轻实现，是因为它已经够用，而且和项目当前规模匹配。

## 为什么 `RouterView` 必须留在布局内部

因为当前后台页面不是一堆平级独立页面，而是：

> 统一壳子下的一组子页面。

所以 `router/index.ts` 里当前主结构是：

- `/login` 独立页面
- `/` 挂 `AdminLayout.vue`
- `dashboard` 和后续动态菜单页都作为 `admin` 的子路由

这正是后台壳子能稳定承接所有系统页的关键。

## 当前用户信息从哪里来

顶部栏展示的用户名不是页面自己存的，而是来自：

- `getAuthUserInfo()`

这又进一步说明当前分层已经很清楚：

- 登录页负责写入
- `utils/auth.ts` 负责读取
- 布局层负责展示

所以如果后面要扩头像、部门、角色摘要，也应该优先沿着这条链路继续加，而不是把用户信息散写到多个页面里。

## 退出登录现在怎么闭环

当前 `handleUserAction('logout')` 会做三件关键事：

1. `clearAuthSession()`
2. `resetDynamicRoutes()`
3. `router.replace('/login')`

这里第二步特别重要，因为它不是只清本地 Token，还会把上一个账号加载过的动态菜单和动态路由一起清掉。

::: warning ⚠️ 退出登录不只是删 Token
如果只清 Token、不清动态路由，那么换账号后前端仍可能残留旧页面入口或旧路由状态。

所以当前实现把“清菜单”和“清路由”一起纳入退出流程，是一个很关键的稳定性处理。
:::

## 当前后台壳子的边界在哪里

可以把 `AdminLayout.vue` 的边界理解成下面这条线：

- 它负责菜单容器、顶部栏、工作标签和页面承载
- 它不负责业务资源请求和资源页面状态

这让系统页后续继续扩展时，不需要反复改壳子本身。

## 最小验收方式

这一页理解或改动完成后，至少可以这样验证：

1. 登录进入后台，确认默认落到工作台
2. 点击侧边栏不同菜单，确认顶部标题和当前页面同步变化
3. 打开多个页面，确认工作标签会跟着增加
4. 关闭某个标签，确认路由回退逻辑正常
5. 点击退出登录，确认返回 `/login`，且旧菜单不会残留
