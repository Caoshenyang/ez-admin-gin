# 配置与文件页实现要点

配置页和文件页都属于系统模块，但它们刚好代表了两种很不一样的资源管理模式：

- `admin/src/pages/system/ConfigView.vue`
- `admin/src/pages/system/FileView.vue`

前者更像“标准键值资源页”，后者更像“上传与资源浏览页”。

::: tip 🎯 本节目标
读完后，你应该能分清什么时候适合参考 `ConfigView.vue`，什么时候更应该参考 `FileView.vue`，避免把所有资源页都写成同一种样子。
:::

## `ConfigView.vue`：最标准的基础资源页之一

配置页当前解决的是：

- 分组
- 键
- 值
- 排序
- 状态

它的特点是：

- 查询条件稳定
- 表格字段固定
- 新增和编辑都围绕同一张表单
- 启停动作清楚

所以它几乎可以看作当前后台里“最标准的基础资源页模板”之一。

## 为什么配置页特别强调 `key` 只读

当前页面有一个非常重要的业务约束：

- 配置键创建后不可改

原因不在前端，而在整体系统设计：

- 配置键会被后端缓存
- 配置键会被其他模块引用

因此当前前端在编辑态下把 `key` 当成只读字段，是一个很符合后台工程习惯的选择。它不是 UI 限制，而是协议和缓存边界的体现。

## 这张页最值得复用的是什么

如果你后面要新增的页面属于：

- 字段稳定
- 关系简单
- 查询和写操作都不复杂

那 `ConfigView.vue` 会比 `UserView.vue` 更适合直接参考，因为它的干扰更少，骨架也更纯粹。

## `FileView.vue`：入口不是弹窗，而是上传

文件页和配置页最大的不同在于：

> 它的第一动作不是“打开新增表单”，而是“上传资源”。

当前 `FileView.vue` 把入口动作放在：

- `NUpload`

而不是 `NModal + NForm`。

这说明页面的第一交互已经从“填表”换成了“提交二进制资源”。

## 为什么文件页依然保留表格和分页

因为上传只是入口，文件资源真正要管理的仍然是：

- 原始文件名
- 类型
- 大小
- URL
- 上传时间

所以文件页后半段依然是标准列表型结构，只是前半段入口换成了上传控件。

## 文件页最有代表性的两处细节

### 第一处：按资源类型展示

当前页面会根据扩展名区分：

- 图片
- 常见文档

并给不同文件类型不同的视觉图标。

这让文件页从一开始就不是“只列字符串”，而是更接近资源浏览页。

### 第二处：复制链接而不是编辑资源

文件页当前的常用动作不是“编辑”，而是：

- 复制 URL

这说明资源页的操作设计不应该机械复用普通 CRUD 页，而要围绕资源的真实使用方式来定。

## 这两张页分别适合参考什么

### 优先参考 `ConfigView.vue`

当你的资源：

- 有固定字段
- 有新增 / 编辑 / 状态切换
- 以表单维护为主

例如：

- 数据字典项
- 系统参数
- 简单业务配置

### 优先参考 `FileView.vue`

当你的资源：

- 核心入口是上传
- 需要展示文件或媒体属性
- 常见动作是复制、预览、下载

例如：

- 附件中心
- 素材管理
- 证照上传页

## 当前按钮权限在这里怎么体现

配置页当前更关注：

- `system:config:create`
- `system:config:update`
- `system:config:status`

文件页当前更关注：

- `system:file:upload`

这也说明按钮权限的粒度会随着资源形态变化，不是每张页都必须拥有同一组动作。

## 最小验收方式

理解或调整这两张页后，至少可以这样验证：

1. 进入配置页，确认查询、分页和新增编辑都正常
2. 编辑一个配置，确认 `key` 不会被当成可随意变更字段
3. 切换配置状态，确认操作反馈和列表刷新正常
4. 进入文件页，上传一个文件
5. 上传完成后确认列表出现新资源，并且 URL 可以复制
