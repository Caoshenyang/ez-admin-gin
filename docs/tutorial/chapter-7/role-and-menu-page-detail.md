# 角色与菜单页实现要点

如果说用户页是“标准管理页模板”，那角色页和菜单页就是第 7 章里更接近后台核心能力的两张页面：

- `admin/src/pages/system/RoleView.vue`
- `admin/src/pages/system/MenuView.vue`

它们的共同点不是“也有表格和弹窗”，而是：

> 页面本身已经开始承担权限结构的编排工作。

::: tip 🎯 本节目标
读完后，你应该能分清角色页和菜单页为什么不能简单按普通 CRUD 页来写，也知道它们分别解决的是哪一层权限结构问题。
:::

## 先看这两张页分别管什么

角色页当前负责：

- 角色基础信息
- 角色启停
- 角色菜单权限
- 角色按钮权限
- 角色接口权限

菜单页当前负责：

- 目录节点
- 页面菜单节点
- 按钮节点
- 菜单层级关系
- 菜单状态

也就是说，两张页虽然都属于“权限体系”，但关注对象不同：

| 页面 | 管什么 |
| --- | --- |
| `RoleView.vue` | 谁拥有哪些权限 |
| `MenuView.vue` | 权限节点本身长什么样 |

## 为什么 `RoleView.vue` 不是普通列表页

角色页的核心交互不是“点编辑弹窗，改完保存”，而是：

1. 先选中一个角色
2. 再在右侧查看这个角色当前拥有什么
3. 最后修改它的菜单、按钮和接口权限

这也是为什么它当前采用的是：

- 左侧角色列表
- 右侧权限面板
- 上方标签页切换不同权限维度

这套结构更像一个“权限工作台”，而不是普通资源列表页。

## 为什么角色页要同时处理菜单、按钮、接口三层

因为当前系统已经把权限明确拆成了三层：

| 维度 | 实际控制什么 |
| --- | --- |
| 菜单 | 页面入口和侧边栏可见性 |
| 按钮 | 页面内具体操作显隐 |
| 接口 | 请求是否被后端真正放行 |

如果角色页只维护其中一层，整个权限体系就会出现“页面能看到但接口不通”或者“接口可用但没有入口”这种割裂现象。

## `NTree` 在角色页里为什么这么关键

当前角色页里最有代表性的组件不是表格，而是：

- `NTree`

它分别承接了：

- 菜单节点选择
- 按钮节点选择

这说明当前前端已经不是把菜单权限当成平铺数组来处理，而是真正尊重了菜单树和按钮树的层级关系。

## 接口权限为什么没有复用树

因为当前接口权限本质上不是菜单层级，而是：

- `path`
- `method`

的组合。

所以角色页会把这部分拆成独立的权限行集合，而不是硬塞回菜单树里。这个设计很重要，因为它避免了把“页面权限”和“接口权限”混成一类结构。

## 菜单页为什么更像“结构维护页”

和角色页相比，`MenuView.vue` 的重点并不是“谁有哪些权限”，而是：

> 菜单体系本身应该怎样被定义。

它要处理的是：

- 根节点
- 子节点
- 按钮节点
- 父子关系
- 展开收起

所以它天然更适合用：

- 树形表格
- 子级新增
- 父节点选择

而不是平铺式资源表。

## 为什么菜单页一定要区分目录、菜单、按钮

当前 `MenuView.vue` 里最重要的模型字段之一就是：

- `type`

它直接影响：

- 当前节点会不会进入侧边栏
- 当前节点会不会变成页面路由
- 当前节点是不是只用来发按钮权限码

因此菜单页不是在维护“一个统一节点列表”，而是在维护三种前端行为完全不同的节点。

## `component` 字段为什么在菜单页里值得重点关注

菜单页里有一个特别关键的输入：

- `component`

它必须和前端 `dynamic-menu.ts` 里的：

- `routeComponentMap`

保持一致。

这意味着菜单页其实是前后端协作最紧密的页面之一，因为这里填错了，页面入口虽然可能存在，但真实路由会回退到占位页。

::: warning ⚠️ 菜单页配错 `component`，前端不一定报错，但页面会退回占位页
这类问题最容易让人误以为是路由挂载失败。其实很多时候只是数据库里的 `component` 字段没有命中前端白名单。
:::

## 这两张页最适合拿来参考什么场景

### 优先参考 `RoleView.vue`

当你的页面需要：

- 先选中一个主体
- 再在右侧配置这主体的权限、资源或关联项

例如：

- 项目成员权限配置
- 租户功能配置
- 审批流节点配置

### 优先参考 `MenuView.vue`

当你的页面需要：

- 维护树结构
- 支持多层级节点
- 区分父级、子级、叶子动作

例如：

- 分类管理
- 组织节点维护
- 多层级功能树维护

## 最小验收方式

理解或调整这两张页后，至少可以这样验证：

1. 进入角色页，确认左侧角色列表和右侧权限面板都能正常工作
2. 修改一个角色的菜单或按钮权限，确认保存后页面反馈正常
3. 修改一个角色的接口权限，确认后端接口行为会跟着变化
4. 进入菜单页，新增一个子级菜单或按钮节点
5. 修改菜单 `component` 或层级关系后，确认前端入口和按钮显隐符合预期
